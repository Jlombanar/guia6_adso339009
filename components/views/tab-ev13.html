Concepto 1

Separar el JavaScript por responsabilidades

Son los archivos que se definieron en la AA4-EV02. Cada uno tiene una sola tarea, así un cambio no rompe lo demás.

Archivos JavaScript y su responsabilidad
Archivo Responsabilidad Funciones principales
api.js Capa de datos. Simula el back-end con localStorage usando las tablas y columnas de la base deportes. iniciarSesion() registrar() crearPedido() pedidosDe()
validacion.js Validación accesible de formularios con la API de HTML5. validarCampo() validarFormulario()
carrito.js Estado del carrito: agregar, cambiar cantidad, quitar, totales. agregar() cambiarCantidad() totalPesos()
main.js Sesión, encabezado común y la lógica de cada página. paginaCatalogo() paginaCarrito()…

¿Por qué una capa api.js?

Las páginas nunca leen localStorage directamente: le piden los datos a API. Cuando construyas el back-end (con PHP, Node o Java) solo cambias este archivo por llamadas fetch() y el resto del front-end sigue igual.

Concepto 2

Eventos, DOM y validación

Tres técnicas que usa todo el ejemplo. Las tarjetas del catálogo se crean desde los datos, no se escriben a mano en el HTML.

Validar al enviar

form.addEventListener("submit", (e) => {
  e.preventDefault();
  if (!Validacion.validarFormulario(form)) return;
  const usuario = API.iniciarSesion(
    form.correo.value.trim(),
    form.clave.value
  );
  if (!usuario) return mostrarAlerta();
  Sesion.iniciar(usuario);
  location.href = "catalogo.html";
});

Paso a paso

Cómo construir el front-end

  1. Copia la interfaz de la AA3-EV03

    El HTML y el CSS ya están listos. Borra los datos escritos a mano (tarjetas, filas de la tabla): ahora los generará JavaScript.

  2. Crea los datos semilla

    En api.js copia los INSERT de tu script SQL como arreglos de objetos, con los mismos nombres de columna.

  3. Enlaza los scripts

    Al final del <head> con defer, en orden: api, validacion, carrito, main. Se usan scripts clásicos y no módulos para que la página abra con doble clic, sin servidor.

  4. Programa los formularios

    Login y registro: valida, muestra el error junto al campo con aria-invalid y lleva el foco al primer error.

  5. Programa el flujo principal

    Catálogo (pintar, buscar, filtrar, agregar), carrito (cantidades, totales, confirmar) y pedidos (tabla y modal de detalle).

  6. Prueba como lo haría el instructor

    Recorre todo con mouse y con teclado, en móvil y escritorio. Prueba errores a propósito: campos vacíos, contraseña incorrecta, más unidades que el stock. Revisa que la consola (F12) no tenga errores.
