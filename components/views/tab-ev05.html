Concepto 1

¿Qué son DDL y DML?

SQL (Structured Query Language) es el lenguaje estándar para trabajar con bases de datos relacionales. Sus sentencias se agrupan según su propósito: unas construyen la estructura y otras manipulan los datos guardados en ella.

DDL · Lenguaje de Definición de Datos

Crea, modifica o elimina objetos: bases de datos, tablas, columnas, índices y restricciones. Trabaja sobre el molde, no sobre los registros.

DML · Lenguaje de Manipulación de Datos

Inserta, consulta, actualiza y borra filas dentro de las tablas ya creadas. Trabaja sobre el contenido.

Principales sentencias DDL y DML
Sentencia Tipo Qué hace
CREATE DDL Crea una base de datos, tabla, vista o índice.
ALTER DDL Modifica una tabla: agrega, cambia o quita columnas.
DROP DDL Elimina el objeto completo, con estructura y datos.
TRUNCATE DDL Vacía la tabla y conserva su estructura.
INSERT DML Agrega una o varias filas.
SELECT DML Consulta filas. Algunos autores la ubican en DQL (lenguaje de consulta).
UPDATE DML Cambia valores de filas existentes que cumplan un filtro.
DELETE DML Borra filas que cumplan un filtro.

Regla de oro: UPDATE y DELETE siempre con WHERE

Sin WHERE, la sentencia afecta a todas las filas de la tabla. Filtra por la llave primaria (id) para modificar exactamente el registro que necesitas. Otras familias son DCL (GRANT, REVOKE) para permisos y TCL (COMMIT, ROLLBACK) para transacciones.

Concepto 2

El motor: MySQL Server y MySQL Workbench

Son dos programas diferentes que trabajan juntos. Confundirlos es el error más común al instalar el entorno.

1

MySQL Server · el motor (SMBD)

Servicio que guarda los datos, interpreta el SQL y aplica las restricciones. Por defecto escucha en localhost:3306. Usa la edición Community, gratuita.

2

InnoDB · motor de almacenamiento

Es el predeterminado de MySQL. Soporta llaves foráneas y transacciones (COMMIT / ROLLBACK), que necesitarás en la EV02.

3

MySQL Workbench · el cliente gráfico

Herramienta visual para conectarse al servidor, escribir y ejecutar SQL, ver resultados en tablas y diseñar diagramas EER.

Funciones de MySQL Workbench
Zona de Workbench Para qué la usarás
SQL Editor Escribir el script. El rayo ejecuta todo el script y el rayo con cursor ejecuta solo la sentencia actual (Ctrl + Enter; ⌘ + Enter en macOS).
Result Grid Ver las filas que devuelve un SELECT. Captura esta zona para el informe.
Output Revisar cada acción con su duración y filas afectadas, por ejemplo 2 row(s) affected.
Navigator · Schemas Explorar bases de datos y tablas. Tras un CREATE, pulsa actualizar para verlas.
Model (EER) Diseñar el diagrama de la base de datos y generar el script con Forward Engineer. Lo pide la EV02.

Modo Safe Updates

Workbench activa por defecto el modo de actualizaciones seguras: rechaza un UPDATE o DELETE cuyo WHERE no use una columna llave (error 1175). Por eso el ejemplo incluye una llave primaria id y filtra por ella. No desactives la protección: escribe filtros correctos.

Ejemplo resuelto · caso diferente

Directorio de proveedores de una cooperativa cafetera

Una cooperativa de Garzón registra a los caficultores que le venden café pergamino. Los ocho pasos siguen el mismo orden del taller de la guía; los datos son ficticios.

  1. Crea la base de datos y la tabla (DDL)

    El teléfono es VARCHAR y no INT: no se opera matemáticamente y puede llevar ceros o el prefijo +57. La llave primaria identifica cada fila. 

    CREATE DATABASE cooperativa_cafe;
USE cooperativa_cafe;

CREATE TABLE proveedor (
  id        INT AUTO_INCREMENT PRIMARY KEY,
  nombre    VARCHAR(40) NOT NULL,
  vereda    VARCHAR(30),
  telefono  VARCHAR(13)
);

  2. Verifica que la tabla exista

    La lista debe incluir proveedor.

    SHOW TABLES;

  3. Revisa la estructura de la tabla

    Muestra cada campo con su tipo, si acepta nulos y cuál es la llave (PRI). 

    DESCRIBE proveedor;

  4. Inserta los dos primeros registros (DML)

    Se omite id porque AUTO_INCREMENT asigna 1 y 2. 

    INSERT INTO proveedor (nombre, vereda, telefono) VALUES
  ('Rosa Cuéllar', 'El Recreo', '3105550101'),
  ('Hernán Polanía', 'Zuluaga', '3115550102');

  5. Consulta todos los registros

    El asterisco devuelve todas las columnas.

    SELECT * FROM proveedor;

  6. Actualiza los datos recién insertados

    Un UPDATE por registro, filtrando por la llave primaria. Vuelve a ejecutar el SELECT para comprobar el cambio. 

    UPDATE proveedor
SET telefono = '3205550111'
WHERE id = 1;

UPDATE proveedor
SET vereda = 'Majo', telefono = '3125550122'
WHERE id = 2;

SELECT * FROM proveedor;

  7. Inserta cinco registros más

    Un solo INSERT con varias filas. El Output debe indicar 5 row(s) affected. 

    INSERT INTO proveedor (nombre, vereda, telefono) VALUES
  ('Luz Marina Trujillo', 'Las Mercedes', '3135550103'),
  ('Óscar Perdomo', 'El Mesón', '3145550104'),
  ('Diana Vargas', 'San Antonio', '3155550105'),
  ('Fabio Ramírez', 'Providencia', '3165550106'),
  ('Yolanda Artunduaga', 'La Cabaña', '3175550107');

  8. Cuenta los registros ingresados

    COUNT(*) es una función de agregación. El alias AS nombra la columna del resultado, que debe ser 7. 

    SELECT COUNT(*) AS total_proveedores FROM proveedor;

Para practicar las demás sentencias

No son parte del taller, pero completan el repertorio DDL y DML. Ejecútalas al final para no alterar el conteo del paso 8. 

-- DDL: agregar una columna a la tabla existente
ALTER TABLE proveedor ADD kilos_mes DECIMAL(8,2) DEFAULT 0;

-- DML: borrar un proveedor puntual
DELETE FROM proveedor WHERE id = 7;

-- DDL: eliminar la base de práctica completa
DROP DATABASE cooperativa_cafe;
