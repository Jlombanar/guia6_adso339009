Motores de bases de datos no relacionales

Un motor NoSQL almacena y consulta datos con modelos distintos al de tablas relacionadas por filas y columnas. Se elige según el tipo de información, las consultas y las necesidades del sistema; NoSQL significa "no solo SQL", no "sin consultas".

Documentos

Agrupan campos en documentos flexibles, parecidos a JSON. Ejemplos: MongoDB y CouchDB. Útiles para catálogos, perfiles y datos que cambian de estructura.

Clave-valor

Guardan cada valor asociado a una clave única. Ejemplos: Redis y Amazon DynamoDB. Se usan en caché, sesiones y búsquedas rápidas por clave.

Familias de columnas

Organizan grandes volúmenes por columnas y distribuyen la carga. Ejemplos: Apache Cassandra y HBase. Se aplican en registros de eventos y series de tiempo.

Grafos

Representan entidades como nodos y sus conexiones como relaciones. Ejemplo: Neo4j. Son útiles para redes sociales, rutas y recomendaciones.

¿Cómo funcionan?

La aplicación envía operaciones al motor para guardar, buscar, actualizar o eliminar datos. Cada familia optimiza una forma de acceso diferente. Muchos motores permiten distribuir datos entre servidores, pero la estructura, consistencia y escalabilidad se configuran según cada producto y caso de uso.

Enfoque principal

MongoDB, Compass y Atlas

MongoDB es un motor NoSQL orientado a documentos. Guarda documentos BSON, que representan datos con una estructura similar a JSON, y los organiza en colecciones.

MongoDB

Es el sistema de base de datos. Su jerarquía es base de datos → colección → documento. Cada documento tiene un identificador único _id y puede contener campos anidados.

MongoDB Compass

Es la aplicación visual de escritorio para conectarse a MongoDB. Permite explorar bases y colecciones, ver documentos, aplicar filtros y ejecutar consultas sin escribir cada operación en la terminal.

MongoDB Atlas

Es el servicio en la nube administrado de MongoDB. Allí se crean clústeres y usuarios, y se controlan las direcciones autorizadas. Compass y mongosh pueden conectarse a un clúster Atlas usando su URI.

Comandos principales

Operaciones de MongoDB con mongosh

mongosh es la consola interactiva para conectarse a un servidor MongoDB y ejecutar comandos sobre bases de datos y colecciones. 

show dbs                              // Listar bases de datos
use vehiculos                          // Seleccionar o preparar una base
show collections                       // Listar colecciones de la base actual
db.createCollection("parque")          // Crear una colección
db.parque.insertOne({ placa: "ABC123" }) // Insertar un documento
db.parque.find({})                     // Consultar documentos
db.parque.findOne({ placa: "ABC123" }) // Buscar un documento
db.parque.updateOne(                   // Actualizar un documento
  { placa: "ABC123" },
  { $set: { kilometraje: 16000 } }
)
db.parque.deleteOne({ placa: "ABC123" }) // Eliminar un documento
db.parque.countDocuments({})            // Contar documentos

Insertar varios documentos

insertMany([ ... ]) agrega varios documentos en una sola operación. En el ejemplo de EV03 se usa para registrar los cinco vehículos solicitados.

Ejemplo de la evidencia

Crear objetos JSON para la colección parque

Cada vehículo es un documento con placa, número de serie, modelo, marca, kilometraje y tipo. El siguiente ejemplo selecciona la base, crea la colección, inserta cinco documentos, consulta y actualiza uno por placa.

Estructura de un documento

Este es un objeto de ejemplo antes de insertarlo en MongoDB:

{
  "placa": "ABC123",
  "numeroSerie": "SN-2024-001",
  "modelo": 2024,
  "marca": "Toyota",
  "kilometraje": 15200,
  "tipo": "SUV"
}
use vehiculos

db.createCollection("parque")

db.parque.insertMany([
  { placa: "ABC123", numeroSerie: "SN-2024-001", modelo: 2024, marca: "Toyota", kilometraje: 15200, tipo: "SUV" },
  { placa: "XYZ789", numeroSerie: "SN-2023-002", modelo: 2023, marca: "Renault", kilometraje: 28400, tipo: "Sedan" },
  { placa: "JKL456", numeroSerie: "SN-2022-003", modelo: 2022, marca: "Chevrolet", kilometraje: 41700, tipo: "Camioneta" },
  { placa: "MNP321", numeroSerie: "SN-2021-004", modelo: 2021, marca: "Mazda", kilometraje: 53600, tipo: "Hatchback" },
  { placa: "RST654", numeroSerie: "SN-2020-005", modelo: 2020, marca: "Kia", kilometraje: 68900, tipo: "SUV" }
])

db.parque.find({})
db.parque.findOne({ placa: "ABC123" })

db.parque.updateOne(
  { placa: "ABC123" },
  { $set: { kilometraje: 16000 } }
)
MongoDB crea automáticamente _id si no se incluye. En una instalación nueva, use vehiculos selecciona la base; esta queda persistida cuando se guarda el primer documento.
