Definir estándares de codificación, de acuerdo con la plataforma de desarrollo elegida

Un estándar de codificación son las reglas que todo el equipo sigue al escribir código, para que se lea como si lo hubiera hecho una sola persona. En esta evidencia defines esas reglas para las tecnologías que elegiste en la AA1-EV01. El ejemplo resuelto son los estándares de la tienda deportes: Node.js con Express, React y MySQL. Como todo es JavaScript, un solo conjunto de reglas cubre el servidor y el cliente.

Criterio de evaluación

Define estándares de codificación de acuerdo con las reglas de la plataforma de desarrollo seleccionada. Instrumento: lista de chequeo IE-GA7-220501096-AA1-EV02. El producto es un informe técnico en PDF con portada, introducción, objetivo y los estándares de codificación: nombramiento de variables, declaración de clases, declaración de métodos, etc.

Decide el idioma y escríbelo

El ejemplo nombra en español sin tildes ni ñ (anio, descripcion), igual que la base de datos y los requerimientos. Inglés también es válido; lo que no se permite es mezclar los dos en el mismo proyecto. Las palabras de Express (req, res, next, Router) se dejan como son.

Concepto 2

Lo que pide la guía, en Node.js

La AA2-EV01 evaluará el código por el nombramiento de variables, métodos, clases y paquetes. En Node.js los «paquetes» son las carpetas y módulos del proyecto.

Carpetas y módulos (paquetes)

Una carpeta por capa: rutas/, controladores/, servicios/, modelos/. Cada archivo dice recurso y capa: producto.servicio.js.

Clases

PascalCase y sustantivo en singular, para entidades y errores: Producto, StockInsuficienteError extends Error. Una clase por archivo.

Funciones y métodos

camelCase con verbo: insertar, buscarPorId, listarTodos, actualizar, eliminar. Los controladores: verbo + recurso (obtenerProducto).

Variables y constantes

const por defecto, let si cambia, nunca var. Arreglos en plural (productos) y sin números mágicos: if (stock <= STOCK_BAJO).

Concepto 3

Declaración de clases y funciones

En una clase, el orden es: constantes estáticas, campos privados, constructor, métodos estáticos, métodos públicos y métodos privados. Toda clase y función exportada lleva JSDoc.

Clase de la entidad

/** Producto de la tabla productos. */
export class Producto {
  static STOCK_BAJO = 5;

  constructor({ idProducto, nombre, precio, stock }) {
    this.idProducto = idProducto;
    this.nombre = nombre;
    this.precio = precio;
    this.stock = stock;
  }

  /** Crea un producto desde una fila de MySQL. */
  static desdeFila(fila) {
    return new Producto({
      idProducto: fila.Id_producto,
      nombre: fila.Nombre,
      precio: Number(fila.Precio),
      stock: fila.Stock,
    });
  }

  tieneStockBajo() {
    return this.stock > 0 && this.stock <= Producto.STOCK_BAJO;
  }
}

Función del modelo (acceso a datos)

// src/modelos/producto.modelo.js
import { pool } from "../config/baseDatos.js";
import { Producto } from "./Producto.js";

const SQL_BUSCAR_POR_ID =
  "SELECT Id_producto, Nombre, Precio, Stock " +
  "FROM productos WHERE Id_producto = ?";

/**
 * Busca un producto por su identificador.
 * @param {number} idProducto - Identificador.
 * @returns {Promise<Producto|null>}
 */
export async function buscarPorId(idProducto) {
  const [filas] = await pool.execute(
    SQL_BUSCAR_POR_ID, [idProducto]);
  if (filas.length === 0) {
    return null;
  }
  return Producto.desdeFila(filas[0]);
}

Los parámetros ? de mysql2 evitan la inyección SQL. En Express 5 los errores de las funciones async llegan solos al middleware de errores, así que los controladores no necesitan try/catch: basta un único manejarErrores al final de app.js.
